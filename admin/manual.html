EC在庫管理の
登録・出品・販売・発送の
流れがひと目でわかる

中古PCなどの仕入れ→出品→販売→発送・在庫引きまでを1画面で管理します。売れたあとの「在庫引き」（他サイトの出品停止）と「発送」はそれぞれ独立した作業です。このページでは登録から販売済み一覧に入るまでの流れを、イラストとともに説明します。

route全体の流れ

商品を登録したら、出品先の状況を記録し、売れたら「売れた」ボタンで受注登録。そのあと在庫引き（他サイトの取下げ）と発送を進めます。両方終わると自動的に「販売済み一覧」に入ります。

出品管理：仕入 → CSV取込 → 出品 → 在庫へ
★「出品管理」タブ

仕入CSVを取り込むと、管理番号を自動生成して在庫に登録

その週に仕入れた商品を、オークションの仕入CSVから一括登録できます。「出品管理」タブの「仕入CSVを取込」を押すだけで、管理番号が自動生成され、メーカー・種別・型番・スペック・仕入値・仕入日まで自動でセットされ、在庫にも同時登録されます。

  • check_circleセット品は台数（総数）で仕入額を割り、個品ごとに1商品として登録
  • check_circleACセット等のまとめ売り（バルク）は個数を保持し、仕入÷個数で1個あたりの単価に
  • filter_9_plus個数はプルダウンから選びます（1〜100個）。在庫一覧の各行と、商品の編集画面のどちらからでも変えられます。一覧のプルダウンは選んだ時点ですぐ保存されます（編集画面を開く必要はありません）。同じ型番をまとめて登録するときに使ってください。個数を2個以上にすると、仕入値の欄に「→ 仕入合計 ¥40,000（50個）」と合計が出ます。仕入値は1個あたりの金額を入れてください（在庫金額は 仕入単価×個数 で集計されます）
  • check_circle仕入CSVの全項目は、各商品の「商品情報 → 仕入情報（CSV）」で確認できます
  • check_circle仕入値が未設定だと「参考売値なし」の警告が出ます
warning同じCSVを2回取り込むと重複登録されます。1つのファイルは1回だけ取り込んでください。
★相場チェック＆出品

型番をクリックして他店の相場を確認 → 出品先を選んで出品

各商品の型番リンク（メルカリ／ヤフオク／ヤフーフリマ／楽天／Amazon）をクリックすると、その出品先サイトでその型番を検索した状態で開きます。他店がいくらで売っているかを見て、価格の参考にできます（参考売値の目安も表示）。

  • check_circle実際に出品したら、出品先をチェックして「出品済みにする」
  • check_circle在庫の出品状況が「出品中」になり、この一覧から外れます
  • check_circle全部出品し終わると出品管理は空＝すべて在庫・販売管理へ移行した状態
個別登録・販売・発送
1商品を登録（仕入れ）

右上の「商品を追加」から（CSVを使わない場合）

管理番号・商品名・種別・メーカー・型番・スペック・仕入日・仕入値・送料・手数料を入力します。管理番号は必須で、CSV取込や販売履歴の照合にも使われるキーになります。

  • check_circle種別はNTPC・TWPC・スマホ など既定の一覧から選択
  • check_circleCSV取込で複数台をまとめて登録することもできます
2出品先を記録

色つきチップで「どこに出しているか」

ドロワーの「出品状況」で、メルカリ・ヤフオク・ヤフーフリマ・楽天・Amazonの状態（出品中／売り切れ／出品停止／保留）を選びます。出品ページのURLも記録でき、一覧のチップから直接開けます。

  • check_circle一覧では商品ごとに色つきチップで状態が一目でわかります
  • check_circleチップ横のリンクアイコンから出品ページへジャンプ
3売れたら「売れた」ボタン

受注情報・発送指示を入力

在庫の商品行にある「売れた」ボタンを押すとドロワーが開き、「販売」欄が自動的に開きます。販売日時・売上・販売先・購入者・電話番号・発送先住所・発送方法などを入力します。販売日時を入れた時点で「販売済み」として扱われます。

  • check_circle販売先を選ぶとサイト手数料率が自動セット（メルカリ10%・Amazon8.4%など）
  • check_circle粗利＝売上−仕入−送料−手数料−サイト手数料−利用料 が自動計算されます
4在庫引き：受注直後、すぐ対応

二重販売を防ぐ最優先の作業

受注した瞬間、他サイトにまだ「出品中」が残っていると赤い「在庫引き待ち」が付きます。発送済みかどうかに関係なく、上部の在庫引きバーの取下げボタンで、他サイトの出品を今すぐ出品停止にしてください。

  • check_circleチャネルごとに「〇〇を取下げ→済」ボタンで記録
  • check_circle出品ページのリンクからそのまま取下げ作業ができます
warningここを後回しにすると、他サイトで同時に売れてしまう「誤出荷・二重販売」の原因になります。
5発送：準備ができたタイミングで

在庫引きとは順番を問いません

発送指示（購入者・住所・電話・発送方法・台数や付属品）を確認して発送したら、「発送済みにする」を押すと出荷日が記録されます。伝票番号や、伝票・QR・写真などの添付ファイルも保存できます。

  • check_circle上部の「発送待ちの商品一覧」バーからワンクリックで発送済みにできます
  • check_circle在庫引き・発送の両方が完了すると「販売済み一覧」に自動的に入ります

schedule「全在庫一覧」表示中は、上に仕入からの経過期間タブ（3ヶ月・6ヶ月・1年以上）が出ます。長期在庫は値下げや出品先の見直しの目安に使えます。
6返品・クレーム対応（あれば記録）

発生日・内容・対応をまとめて残す

ドロワーの「返品・クレーム対応」で、発生日・内容・対応内容を記録し、対応済みならチェックを入れます。記録した商品は上部の「返品・クレーム」カードから一覧でき、未対応件数もひと目でわかります。

7自社ショップに出品する

「ショップ出品」タブから、在庫をそのままショップへ

上部の「ショップ出品」タブを開くと、在庫の商品が一覧で並びます。写真を選び、表示名・販売価格・商品説明を入力して「ショップに公開する」を押すだけで 8ec.jp/shop/ に商品が並びます（商品ごとにドロワーを開く必要はありません）。

  • photo_library写真は「写真を選ぶ」から、そのまま選ぶだけ。ドラッグ＆ドロップでも、スマホならその場で撮った写真でも追加できます。最大8枚まで並べられ、1枚目がメイン画像です（サムネイルの「メインに」で入れ替え）
  • add_link画像はURLでも追加できます。写真欄の下にある入力欄にURLを貼って「URLで追加」を押すだけです。カンマや改行で区切れば複数まとめて入ります。撮影せずにメーカー・仕入先から提供された画像を使う場合に便利です
  • payments値付けはボタン1つ。販売価格の欄の横に「¥◯◯◯ を入れる」ボタンが出ます（仕入×1.5の目安）。そのままでよければ押すだけで入力できます
  • storefrontまとめて公開できます。上部の「価格入力済みをまとめて公開」を押すと、価格が入っていてまだ公開していない商品を一度に公開します（実行前に件数を確認するダイアログが出ます）。「価格入力済み・未公開」タブで対象を先に確認できます
  • credit_card決済リンクはボタン1つで自動作成。「決済リンクを作成」を押すと、Stripeに商品・価格・決済リンクがまとめて登録されます（手で作る必要はありません）
  • check_circle中古品は1点ものなので、1回購入されるとリンクは自動で締め切られ、二重販売を防ぎます
  • check_circle価格を変えたときは「決済リンクを作り直す」を押してください（古いリンクは無効化されます）。価格がずれている間は警告が出ます
  • check_circleショップに並ぶ条件は「公開する」＋「販売価格あり」＋「未販売」の3つ。価格を入れずに公開しようとすると警告が出ます
  • check_circle売れた商品（販売日時あり）は自動的にショップ一覧から外れます
  • fact_check在庫一覧に棚卸の印が出ます。その月の棚卸で確認した商品には「棚卸済み」、見つからなかったものには「棚卸：なし」が管理番号の横に付きます（翌月になると消え、また未棚卸から始まります）
  • info「出品管理」タブの件数とは一致しません。自社ショップへの公開と、メルカリ・ヤフオクなど各モールへの出品は別々に管理しているためです。ショップ出品タブの上部に「在庫◯点＝公開中◯点＋未公開◯点／うち他モール出品中◯点」の内訳を出しているので、そこで突き合わせられます
info初回のみ「admin/supabase-setup.sql」と「shop/supabase-shop-setup.sql」の実行、および Edge Function「create-payment-link」のデプロイ（＋STRIPE_SECRET_KEY の設定）が必要です。
8CSVで一括登録・更新

まとめて取り込み・書き出し

右上のCSV取込で複数商品をまとめて登録・更新できます。管理番号が同じ行は上書き更新され、CSVに無い列は既存の値のまま保持されます。CSV出力で現在の一覧をバックアップできます。

  • check_circle管理番号・商品名・種別・メーカー・型番・仕入・出品状況・販売情報などに対応
  • check_circle取込は必ず一度CSV出力したファイルと同じ形式で行います
9月次集計で振り返る

月ごとの販売数・売上・粗利

上部タブの「月次集計」で、販売日時をもとに月別の販売数・売上合計・サイト手数料・粗利合計を確認できます。年は左右の矢印で切替、月の行をクリックすると、在庫・販売管理画面にその月の販売分だけを絞り込んで表示します。

infoサイト手数料率が未入力の販売について。手数料率の欄ができる前に登録した販売など、率が空のままの商品は販売先の既定率（メルカリ・ヤフオク・楽天 10%／ヤフーフリマ 5%／Amazon 8.4%）で計算します。以前はこうした販売のサイト手数料が0円として扱われ、粗利が手数料のぶんだけ多く出ていました。該当件数は表の下に表示されます。個別に率が決まっている場合は、商品の詳細から手数料率を入力すればそちらが優先されます。
10毎月の在庫報告をする

棚卸と在庫CSV

上部タブの「棚卸・在庫報告」で、月ごとの実地棚卸と、報告用の在庫CSV出力ができます。「未棚卸」タブに、その月にまだ確認していない在庫だけが並びます。確認したものは一覧から消えて「棚卸済み」タブへ移るので、未棚卸が0になれば、その月の棚卸は完了です。

event_repeat毎月ゼロから始まります。翌月になると、また全件が「未棚卸」に並びます（8月に確認したものも、9月にはもう一度確認する対象になります）。前月の記録は消えないので、対象月を8月に戻して「棚卸済み」タブを開けば、8月に確認した一覧をいつでも見られます。
  • tabタブは4つ。「未棚卸」（既定・その月にまだのもの）／「棚卸済み」（その月に確認したもの）／「なし・要確認」（現物が見つからないもの）／「すべて」。それぞれ件数が出ます
  • search1. 検索して絞り込む。管理番号・商品名・型番で検索すると、条件に合う在庫だけが並びます。保管場所・種別でも絞れるので、倉庫を回りながら「柏の未棚卸だけ」を表示して進められます
  • check_box2. チェックを入れる。行の左のチェックボックスを押します。「表示中の◯件をすべて選ぶ」で一括選択もできます
  • check_circle3.「棚卸済みにする（日時を記録）」を押す。選んだ商品すべてにその場の日付と時刻が自動で入り、「未棚卸」の一覧から消えて「棚卸済み」タブへ移ります。入力は不要です
  • scheduleいつ棚卸したかが各行の右側に出ます。商品を検索すれば「棚卸済み 2026/8/3 05:57」のように最後に確認した日時がすぐ分かります。一度も確認していないものは「未棚卸」、先月までに確認して今月まだのものは「◯月は未実施」と出ます
  • sort並び順は「棚卸が古い順（未棚卸が先）」が既定です。まだ確認していないもの、前回から一番間が空いているものが上に来るので、上から順に片付ければ毎月の棚卸が終わります。「新しい順」「管理番号順」「仕入が古い順」にも切り替えられます
  • calendar_month「最終棚卸月」で絞り込めます。「2026年07月に棚卸（12点）」のように月ごとの件数が出るので、先月やったきりのものや一度も棚卸なしだけを表示して進められます
  • storefront各行に出品先が出ます。メルカリ・ヤフオク・楽天・Amazon・自社ショップのうち、いま出品中のものが色付きで並びます。出品停止や売り切れの記録がある場合はその状況も添えます。棚卸しながら「これは今どこに出ているか」が分かります
  • report_problem見つからないものは、チェックしてから「なし」「要確認」を押します。押し間違えたら「記録を取り消す」で戻せます
  • task_alt確認が終わったら「棚卸を確定」。その月の在庫点数・在庫金額・あり／なし／要確認の件数が記録として残り、画面下の「これまでの棚卸」で前月と比べられます
  • download「在庫CSVを出力」で報告用のファイルを作れます。管理番号・種別・メーカー・型番・仕入日・経過日数・仕入金額・保管場所・出品状況・棚卸結果・棚卸日時が入り、末尾に合計行が付きます
  • report_problem「差異CSV」は「なし」「要確認」だけを抜き出します。原因を追う作業に使ってください
info個数が2個以上の商品（バルク品）は、在庫金額に仕入単価×個数で計上されます。
初回のみ、Supabase の SQL Editor で「admin/stocktake-setup.sql」を実行してください。
11決算の数字を出す

基準日で締めた金額を出す

上部タブの「決算資料」で、基準日を指定してその日時点の金額を出せます。決算期末は8月末なので、開いた時点で 8月31日 が入っています（違う日にしたいときは日付を変えるか、「期末（8月末）にする」で戻せます）。

  • inventory① EC在庫金額。基準日時点で在庫だった商品の仕入原価（仕入単価×個数）です。基準日より後に売れたものは在庫として数え、基準日より後に仕入れたものは除きますので、9月に入ってから8月末の数字を出せます
  • payments② EC未収入金。基準日までに売れて、入金日が未入力のものの売上合計です
  • receipt_long④ 未請求売上。基準日までに売れて、請求日が未入力のものの売上合計です
  • download各カードの「CSV」で明細つきファイルを出力できます（末尾に合計行つき）。「3項目まとめてCSV」は3つの金額を1枚にまとめたもので、経理へそのまま渡せます
edit_calendar請求日・入金日の入れ方。商品の編集画面の「販売」セクションに、出荷日・伝票番号の下へ請求日と入金日の欄を追加しました。空欄のあいだは「未請求」「未入金」として集計されます。
③ 期末仕掛品は、案件ごとの原価（人件費・外注費・材料費）を持っていないため、この画面では算定できません。
初回のみ、Supabase の SQL Editor で「admin/closing-setup.sql」を実行してください。
ドロワー（編集画面）は必要な項目だけ自動で開く
セクションが折りたたみ式になっています
商品情報・出品状況・8 SHOP公開設定・販売・返品・クレーム対応の5つのセクションは、見出しをクリックすると開閉できます。データがすでに入っている項目だけ自動的に開いた状態で表示されるので、スクロールが長くなりすぎません。
  • 新規登録時：商品情報だけが開いた状態で始まります
  • 出品状況を記録済みの商品：出品状況が開いた状態
  • 「売れた」ボタンから開いた場合：販売セクションが開いた状態
  • 返品・クレームを記録済みの商品：返品・クレーム対応が開いた状態
「在庫を戻す」ボタンとは？
販売セクション内の「在庫を戻す」ボタン（旧「戻す」）を押すと、販売日時・売上・購入者・発送情報など販売・発送に関する情報だけがクリアされ、商品は在庫に戻ります。出品状況（メルカリ等のチップ）はそのまま残ります。誤って「売れた」にしてしまった時や、注文がキャンセルになった時に使います。
よくある質問
ログインできない・0件になる
共有ID zimu でログインしているか確認してください。別のIDだとデータが見えません（同じIDでみんな同じデータを共有します）。反映されない時は Ctrl+F5 で再読み込みしてください。
サイト手数料率が自動で入るのはなぜ？
販売先を選ぶと、その販売先の目安手数料率（メルカリ10%・ヤフオク10%・ヤフーフリマ5%・楽天10%・Amazon8.4%）が未入力の場合だけ自動セットされます。実際の率が違う場合は手で書き換えてください。
CSV取込でエラーが出る
ヘッダー行に「管理番号」列が必要です。まず一度「CSV出力」でファイルをダウンロードし、その形式（列の並び）に合わせて編集してから取り込んでください。
「在庫引き」と「発送」はどちらを先にやるべき？
順番は問いませんが、在庫引きは受注直後・発送を待たずにすぐ行ってください。二重販売（他サイトでも同時に売れてしまうこと）を防ぐためです。発送は準備ができたタイミングで進めれば大丈夫です。
Stripe決済リンクとは？
Stripeダッシュボードで商品ごとに作成した決済用URL（https://buy.stripe.com/…）を、ドロワーの「8 SHOP公開設定」に貼り付けます。8/shop の購入ボタンからこのリンク先で決済できます。
粗利はどう計算されている？
粗利 ＝ 売上 − 仕入値 − 送料 − 手数料 − サイト手数料（売上×手数料率） − プラットフォーム利用料、で自動計算されます。月次集計の粗利合計もこの計算式の合計です。
